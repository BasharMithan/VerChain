# Hashing

These IDs structures are defined in Verchain v0.4.1 and above.

This document explains how the hashing mechanism is done in Verchain. Almost each data model in Verchain must generate a hash (or take one), so hashing is the core of Verchain.

## Hashing Algorithm

The hashing algorithm that Verchain uses to produce a hash is **SHA-256**, it's recommended here for three practical reasons:

- **Tamper detection:** A digest let's you check file integrity without comparing whole file byte by byte.
- **Small on-chain reference:** A system can record a digest or commitment while keeping the document itself off-chain.
- **Interoperability:** It's a standardized hash used in cryptographic workflows, including credential-proof schemes.

## Hashed IDs

The `User`, `Credential`, and `Authority` all have their own generated hash ID, used to verify the input data, and perform a decentralized ownership checks.

### User (`HID`) - Holder ID

The `HID` is a combination of the following information:

```python
HID = sha256(f"{name}:{nationalID}:{birthDate}")
```

### Authority (`AUTHID`)

The `AUTHID` only needs the `authorityName` & `authorityID`:

```python
AUTHID = sha256(f"{authorityName}:{authorityID}")
```

### Credential (`CID`)

The `CID` is the most important ID, and it is build out of the following data:

- The `documentHash` - Generated by hashing the document and the document ID only.
- The `documentID` & document itself - Passed from the authority when checking the ownership.

```python
CID = sha246(f"{documentHash}:{documentID}")
```

### The Holder Credential ID (`CHID`)

This is the ID that is stored on-chain, it's a combination of all the generated IDs above.

```python
CHID = sha256(f"{HID}:{CID}:{AUTHID}")
```
