# What's new in release 0.3.0

This release focuses on reliability, testability, and operational readiness. The project moves further toward a more usable blockchain-based Credential verification system by improving validation, network/API coverage, and configuration control.

## Highlights

1. Automated test coverage
   - Expanded the project’s `pytest` suite to validate the main blockchain flows, API layer, block validation logic, chain synchronization, and verification behavior.
   - Added regression coverage for registration, duplicate detection, invalid request handling, chain validity checks, and API responses.
   - This improves confidence in the system and makes future changes safer.

2. API support for external interaction
   - Added a FastAPI router for the core system operations, including:
     - `POST /register` to register a verified Credential on-chain.
     - `POST /check` to validate whether a user/credential/issuer combination is approved.
     - `GET /chain` to retrieve the current ledger state.
     - `GET /status` to inspect node metadata and blockchain health.
   - This makes the platform easier to integrate with web applications, verification services, and external clients.

3. Centralized project configuration with `Settings`
   - Added the `Settings` class under the configuration layer to define runtime behavior and operational parameters.
   - The initial configuration includes ledger difficulty and execution mode controls, making the system easier to tune without modifying core logic.
   - This provides a cleaner foundation for future network and performance tuning.

4. Stronger validation and ledger safety
   - Improved the safeguards around submission and chain integrity so invalid or conflicting data is rejected before it can affect the ledger.
   - The combination of validation and blockchain checks helps prevent corrupted or inconsistent Credential records from being accepted.

5. Better project structure for long-term maintainability
   - The codebase now separates concerns more clearly across API communication, blockchain management, validation, and configuration.
   - This prepares the project for future features such as richer CLI tooling, network improvements, and extended Credential workflows.

## Why this matters

The 0.3.0 release strengthens the system’s foundation in three important areas:

- Reliability: automated testing reduces the risk of regressions.
- Interoperability: the API layer enables easier real-world integration.
- Configurability: centralized settings make operational tuning easier.

## Example workflow

A typical verification flow in this release looks like this:

1. A user submits their Credential and issuer information via the API.
2. The system validates the data and creates the Credential record.
3. The Credential is mined and stored in the blockchain ledger.
4. A verifier checks the recorded CHID against the submitted user, credential, and issuer details.
5. The API returns an approval or rejection result.

## Planned next steps

The project continues to evolve toward broader functionality and usability, with planned work focused on CLI support, richer developer tooling, and additional system improvements.
